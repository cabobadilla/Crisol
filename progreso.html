◇ Propuesto requiere backend o key

Agente LLM real para el challenge

Una app estática no puede guardar una credencial sin exponerla. El challenger determinístico por reglas prueba el mecanismo; el LLM es una capa encima.

  • Backend mínimo o proxy que guarde la key
  • Un LLM real que objete sobre las reglas ya verificadas
  • Mantener el veredicto determinístico como base auditable

→ Requiere tu OK. Depende de decidir dónde vive la key.

⏸ En pausa agregar reglas

Reglas de challenger 4..N + framework configurable

La Etapa 1 trae 3 reglas, una por gap estructural. Las demás son la misma máquina con otra condición — no cambian la arquitectura.

  • Calidad de la métrica, tamaño, apalancamiento real en agentes, riesgo de dependencia del proveedor
  • Permitir definir el framework en vez de tenerlo fijo

→ Sin fecha. Se decide tras ver la Etapa 1 en uso.

Decisiones

  • El framework es el del harness — No se inventa uno nuevo: se productiza el que ya funciona (supuesto S-3)
  • Valor y metrica son Etapa 1, no diferido — Correccion del usuario: una idea que no dice que cambia y como se mide no esta definida
  • El challenger tiene 4 reglas, una por gap estructural — R1 sin problema, R2 sin valor o metrica medible, R3 sin referencias, R4 sin criterio de terminado
  • Challenger determinístico por reglas — El mecanismo que importa es que RECHACE, no que use un LLM (supuesto S-4)
  • Un solo artefacto, sin backend — POC estático, igual que MyHermesTest
  • Anti-alcance: no ejecuta, solo define — Su dominio termina donde empieza la construcción
  • Se reutiliza el diseno Pizarra (piel slate) de MyHermesTest — Pedido del usuario al aprobar G1. Fuente de verdad: docs/DISENO-PIZARRA.md, extraido del index.html con procedencia y linea
  • Un diseno reutilizado arrastra sus defectos — Pizarra trae H-1 (la barra desborda a 375px) como requisito de correccion, no como herencia
  • El despliegue es un requisito, no un pendiente — Pedido del usuario: Cloudflare es su servicio preferido. Se define local Y cloud desde el diseno (HU-8)
  • Cloudflare Workers con static assets, no Pages — Cloudflare recomienda 'start new projects with Workers'. Una app estatica sin backend no paga invocaciones: los requests de assets son gratis
  • El arquitecto tiene skill de Cloudflare — cloudflare-architecture, instalada desde el harness: limites reales del plan free, eleccion de bindings, paridad local/cloud y trampas verificadas
